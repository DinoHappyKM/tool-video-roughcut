# XML 交接：素材自檢與必要轉檔

版本：0.3.1｜更新：2026-10-04｜[流程](WORKFLOW.md)｜[交付表](templates/04_DELIVERY_CHECKLIST.md)

當需求卡指定 XML／DaVinci／其他 NLE 交接，或使用者準備匯出 XML 時主動執行。素材盤點便先標記可能的問題，交付前依最新工程再次檢查；不等到使用者遇到離線才處理。只有影片出片、沒有 XML 需求時不強制轉檔。

## 先分辨三種問題

| 層級 | 檢查與證據 | 採取動作 |
|---|---|---|
| 影片能否被目標軟體讀取 | 來源實際播放、規格、解碼錯誤；目標 OS／軟體版本 | 確認有讀取問題或具體格式風險時，建立適合目的的相容副本 |
| XML 是否正確引用影片 | 實際路徑、名稱碰撞、來源影格率／時間碼／區間、匯入日誌 | 缺路徑先修復引用；影片可播放但 XML 不能匹配，不直接判為檔案損壞 |
| 功能能否經 XML 交接 | 字幕、文字、動畫、透明度、效果、轉場、聲音處理等 | 按目前匯出器與目標軟體支援交付 SRT、已渲染動畫／音訊或在目標端重建；轉檔不能讓任意效果變成可編輯功能 |

線上圖庫、免費素材、手機影片都可接受相同檢查。副檔名、來源網站或長檔名不能單獨證明不支援；兩支影片同為 MP4 也可能有不同來源資料。XML 是時間線交換資料，不是影片編碼。

## 1. 交接預檢

確認目標軟體、版本／OS、XML 格式、時間線版本、尺寸、影格率與原生多機要求，寫入需求卡。讀最新工程及人工修改，保存交接前版本。

對實際入選及引用素材記錄：
- 素材身分、目前檔案位置、唯一名稱與來源關係；本機檔存在且可讀。雲端或生成素材先取得本機可用來源。
- 視訊編碼／容器、影格率與 VFR、時長／影格數、起始時間碼／PTS、尺寸／像素比例、旋轉、位深／色彩／HDR／透明度，以及需要的音軌與聲道。
- 所有取用區間、變速／裁切／幾何位置與對應聲音；實際來源時間和時間線位置分開記錄。
- 匯出前警告及已知不攜帶的元素，區分「確定需要處理」「有風險待實測」「目前可用」，不把風險直接報為失敗。

來源 25 fps 放入 30 fps 時間線本身不構成錯誤。重點是來源描述、實際媒體、來源取用範圍及目標匯入解讀一致；不為方便把全部素材固定為 30 fps。

依現行官方文件核對支援。2026-10-04 ChatCut 文件列出字幕、GIF、未渲染動畫、純色、SVG、文字、部分幾何／效果／轉場可能掉失；本表是查核起點，不是所有版本的固定支援清單。[ChatCut XML 文件](https://chatcut.io/docs/export-xml)

## 2. 選擇最少需要的處理

已可用的來源直接保留。只有引用錯誤時先更正來源或重新註冊、匯出；有讀取問題、規格不一致、經驗證的匹配失敗，才為受影響素材建立相容副本。使用者已要求批次正規化時可照該範圍執行，不另要求一次通用批准。

一般 SDR 庫存 B-roll 可參考本批通過的方法：MP4／H.264／8-bit 4:2:0、固定影格率、從零開始、短且唯一的檔名。影格率依交接目標選，本批是 30 fps。優先保留原始尺寸、像素比例、橫直方向、正常速度與需要的音軌，不默默裁切、靜音或加入情境示意文字。

這是相容副本，不是無損母檔；有 10-bit／HDR、透明度或慢動作需求時，先確認目的，選實測可讀且保留所需資訊的格式。不把 ProRes 10-bit 一律降為 8-bit，不把 50／60 fps 原片一律降幀而失去慢動作用途。

庫存 B-roll 歸零與多機 A-roll 同步不同。相機／錄音素材若要轉檔，保留原始母檔、時間碼及同步對照；必要時重建明確映射並驗證同步前中後及重啟處，不能套用 B-roll 歸零後宣稱同步不變。

## 3. 建立與驗證副本

優先用當前工具提供的媒體轉檔功能；沒有合適工具時可用本機 FFmpeg。先讀工具契約與可用編碼器，不保存這次工程的臨時參數或資產 ID 作為通用配方。

按已授權範圍自動完成檢查、另存相容副本、驗證及來源更新。先以代表素材確認規格與畫面，再批次處理；昂貴操作或會丟失需求資訊但尚無決策時才釐清。外部 NLE 無法自動操作時，完成可執行部分，交付具體匯入樣本並把人工驗收明列待測。

- 轉檔另存，不覆蓋原檔；失敗或被占用時保留完成的副本及待處理清單，排除問題後再接續。
- 保存來源 → 副本對照、實際處理選項、規格、時長與雜湊（有實算才填）。
- 核對完整解碼、首中尾與取用區間畫面、速度、尺寸、色彩及需要的聲音。長度差異記錄且須足以涵蓋全部剪點。
- 已有驗證通過副本就沿用，避免再次有損編碼；未必要的來源保持原樣。

[FFmpeg fps 濾鏡](https://ffmpeg.org/ffmpeg-filters.html#fps) 是依時間戳重複／捨棄影格的工具；固定影格率不代表畫面變流暢或品質無損。實際工具可用性與輸出另測。

## 4. 讓時間線真正使用新來源

加入素材庫不等於更換時間線。檢查所有受影響版本，將實際片段引用換成新副本，保留成片起訖、來源相同內容、速度、裁切、放大、透明度、淡入淡出及原聲音安排。

來源時間基準改變時換算取用位置，不能盲目照抄 sourceIn。工具不允許改既有來源時，可在非波紋操作中替換片段並回讀。先核對完整來源與片段，再比較未受影響的主聲音、字幕、封面、其他軌道、作品及同步母版。

既有動畫片段使用範圍與來源可用長度不一致時，先判斷實際內容及意圖；不可為通過驗證任意灌大 metadata。首輪有經查看的長度資料補正個案，不是所有剪輯的通用修復。

原始素材預設保留。只有使用者明確要求清理時，核對新副本、全部時間線引用和其他已知工程用途後再刪除；優先送資源回收筒，保存對照，提醒工程備份不一定包含媒體。被占用的空目錄不強制關閉未保存程式或跨程序控制代碼，記錄待清理。

## 5. 匯出後再次核對

從 APP 或可用的原生匯出工具產生目標軟體 XML；不預設助手自行重寫 XML 比 APP 更可靠。保存 XML、媒體位置、SRT、渲染元素、必要處理後音訊、參考影片與缺失表。

解析 XML 時先建立 file ID 的來源定義表，後續只有 ID 的引用要回查，不誤認為缺路徑。核對：
- 所有來源路徑存在、檔名與副本相符；路徑含空格／中文時 URI 解碼正確，沒有舊資料夾或暫存來源遺留。
- 來源影格率／時間碼／長度與實際檔案相容；in/out 位於來源有效範圍，start/end 與目標剪點及總長一致。
- 副本與更新後工程版本一致。已有 XML 不會因移動影片或更新素材庫自動變更，必須重新匯出。
- 不支援的項目有交接方案；匯出完成通知或警告不能替代這些檢查。

字幕另交 SRT，保存繁體、全文與相對時間；SRT 不攜帶原有字型、美編或位置。目標端重設繁中字型、單行、畫面置中並核對實際顯示。若保留處理後聲音是必要條件而 XML 無法重現，就交付經確認的處理後音訊，對齊時間線起點、保留聲音版本且避免雙重播放；不自行再降噪當作 XML 修復。

透明動畫依目前原生渲染／匯出能力及帳號決定；保留透明度並實際核對，不能用不含 alpha 的通用 MP4 取代。[字幕與音訊匯出](https://chatcut.io/docs/export-video-audio-subtitles)

## 6. 在目標軟體驗收

匯入新的測試時間線；核對 B-roll 前中後及邊界、剪點、構圖、速度、人聲、聲道與同步，並對照參考成片。素材讀取、XML 連結、效果重建與聲音聽感各自填結果。需要重建的部分記錄工具、完成狀態和工時。

工具可量測／回讀的先完成，無法自動播放的項目交給使用者。沒有實際達芬奇播放就不標本機通過；使用者回報成功記為使用者實測，附回覆與範圍，不能擴張成每個效果、第二批或學生都通過。

本輪首批相容庫及正式短長版交接已收到成功回報，見 [首輪交接結果](pilots/PILOT_001_XML.md)。後續每批仍執行本檢查。
