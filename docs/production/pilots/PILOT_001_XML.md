# PILOT_001｜XML 相容素材與正式作品交接

更新：2026-10-04｜[首輪試跑](PILOT_001.md)｜[XML 規則](../XML_HANDOFF_RULES.md)

## 已完成與證據

原 B-roll 在達芬奇媒體池可播放，從官方 APP XML 匯入卻無法匹配；日誌定位到一段 B-roll 的來源搜尋失敗。影片來源資料與 XML 描述有差異，但沒有證明唯一根因是長檔名、時間碼或圖庫影片損壞。

本批九支 B-roll 建立／沿用 MP4 H.264、8-bit、固定 30 fps、起始時間零、短且唯一名稱的相容副本；尺寸、像素比例與橫直方向保留，完整解碼通過。本批本來無音軌。使用者從 APP 匯出九段驗收時間線並回報達芬奇匯入成功，截圖直接確認原先失敗的鏡前保養片段正常。

使用者其後要求把相容庫移至最外層、清理舊來源，並更新正式短長版：
- 九支新來源逐檔 SHA256 核對；正式 59.8 秒短版的一段與 152.1 秒主版本的三段 B-roll 已實際換來源。
- 包裝初稿及九段驗收時間線也更新，共五份時間線十七個片段；十二張舊素材卡刪除回報未移除其他片段。
- 兩部正式作品非 B-roll 片段欄位、六份字幕檔及 B-roll 其他欄位保持；母版、主聲音、人工裁切與封面安排沒有重建。
- 既有兩個動畫資產的可用長度資料經核對補為三秒，修復片段使用範圍驗證；不當成任意擴張 metadata 的通用方法。
- 原生匯出兩份新 XML，所有來源檔存在，B-roll 指向新位置，來源 fps／時間碼／取用範圍及成片剪點靜態檢查通過。字幕另交繁體單行 SRT，原生工程字幕不改。
- 舊原片及先前副本只在使用者明確要求下送入資源回收筒；來源對照與工程備份保留在本機。空目錄被占用的清理與 XML 播放驗收分開處理。

最後使用者回覆「測完OK了」，並要求把必要轉檔、自檢及來源更新納入技能。因此記為本輪正式作品 XML／達芬奇交接的使用者實測通過；回覆所指範圍依前一輪兩部作品測試安排，不補造使用者實際匯出檔名或逐項播放記錄。

## 可重用的結論

XML 需求應啟動素材與功能預檢；必要時另存相容副本，實際更新時間線，再原生匯出與驗收。字幕、美編、動畫與處理後聲音獨立交接。只把副本加入素材庫、只修檔名或只看匯出通知都不足以完成交接。

本批同時調整編碼、影格率、時間碼、名稱與來源引用，不能分離唯一根因；不禁止使用外部圖庫，不把所有影片都固定轉為 30 fps，不把 B-roll 歸零規則套用到多機 A-roll。詳見 [通用規則](../XML_HANDOFF_RULES.md)。

私人來源路徑、工程／素材 ID、完整逐字稿、訪談內容與影片均留在本機；此頁只保存匿名化方法及證據界線。
